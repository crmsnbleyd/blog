Git config for multiple accounts

Posted on Dec 20, 2025 in blogpost

I use git, as the version control system both at my workplace and to store my personal code (including the source of this blog).

I use different e-mails for personal and work repositories, as well as different SSH keys for different accounts (this is because Github, at least, does not allow different accounts to use the same key, which I was not sure of, but Ariel confirmed on fedi).

After a bunch of trial-and-error, I have figured out a way to do ssh for two different github accounts using different keys on the same device. The .sshconfig looks a bit like this:

Host work
  User git
  HostName github.com
  IdentityFile ~/.ssh/id_work_github

Host personal
  User git
  HostName github.com
  IdentityFile ~/.ssh/id_personal_github

So, if I want to clone a work repo, I need to do git clone work:<WorkOrg>/<RepoName>.git, and if I want to do the same using my personal account, git clone personal:<Org>/<RepoName>.git, and it just works.

I have to remember to use the correct prefix, work or personal, and if I use the wrong one, I get an error saying I can’t access the repository. To do this, I either have to change the original clone url copied from the forge, which would be something like git@github.com:<Org>/<RepoName>.git, or type the whole thing out.

Turns out, git allows one to use text substution for URLs, which fixes the problem!

[url "work:<WorkOrg>/"]
    insteadOf = https://github.com/<WorkOrg>/
    insteadOf = ssh://git@github.com/<WorkOrg>/

[url "personal"]
    insteadOf = https://github.com
    insteadOf = ssh://git@github.com

git substitutes using the longest matching URL, so if the repository is under the work Org, it will use the first rule, and otherwise use my personal key+account.

This is not the only problem though. Git forges do not use the ssh key (or your username+password) to identify the committer, but rather the email address and name set in your git config. Yes, this means anyone can spoof your identity on their commits (which is why we have signed commits). How you fix this, is you run the following commands per repository if you are using a different name and email than the ones you have set globally:

git config set user.name "Drew Jose"
git config set user.email "abc@example.com"

If I forget this, however, the commits will be seen as authored by my work account, which I don’t want. To automatically set this up, there’s two steps:

  1. Keep all the personal repositories in one folder, and in the root create a .gitconfig file containing the name and email you want

    [user]
email = abc@example.com
name = Drew Jose

  2. Add a conditional inclusion to the global git config. It includes a given .gitconfig file when git commands are run inside some directory. This should be after the globally defined [user] config, so that this takes precedence.

    [includeIf "gitdir:~/code/"]
path = ~/code/.gitconfig

This is quite neat and does what I want. One could extend this to add even more sorts of dynamic inclusions per folder.
