Compiling targets deep in a directory with make

Posted on Aug 11, 2023

In this post I'm going to be talking about GNU make, an awesome tool that few people outside of the usual suspects (read: C programmers) use.

I'm specifying the GNU version because:

  • Most people have it by default anyway (unless you're on Windows, in which case, my condolences, and you can probably use chocolatey to install it)
  • %, a feature I'll be using in this example is implementation-defined according to POSIX.

Background

The pelican theme I'm using as a base for my own, Flex, uses Less (though that is being phased out at the time of writing) as a CSS preprocessor.

Less files cannot be used in the browser directly without compiling, unless you use a javascript library to do it client-side, which sounds awful. The alternative is to compile the less files using lessc to convert it to regular old CSS before shipping it to your website.

Like a dumbass, I had been running the compiler manually, only choosing the files that I had changed. I'm not sure why I did not automate the process even earlier.

Enter Make

The elevator(or lift, if you're British) pitch for Make is: you give it a set of instructions, and you can call those instructions with a short name, saving a bunch of repetition.

If that were all, though, one would just use shell scripts. The actual pitch for make is that you can specify targets and sources and specify dependencies between them, so that you only build the files whose sources you have actually modified, saving you and the computer a ton of effort.

Here's a minimal example of what I'm talking about:

LESSDIR=$(CURDIR)/themes/Solarized-Flex/static/stylesheet

vpath %.less $(LESSDIR)

$(LESSDIR)/%.min.css: %.less variables.less
    lessc $< --clean-css="--s1 --advanced --compatibility=ie8" $@

less: $(LESSDIR)/style.min.css $(LESSDIR)/dark-theme.min.css

.PHONY: less

What's going on here

You can set variables and refer to them as $(VARIABLE). CURDIR is a variable pointing to the working directory of make.

vpath tells make to look for files ending with the extension .less in LESSDIR.

Now we get to the fun stuff: for targets in LESSDIR ending in .min.css, we have the source files %.less and variables.less. Note that make already knows to look for these files because of vpath and we don't need to prepend them with the directory path. % acts as a wildcard which matches everything, so this line reads something like: "for every target abc.min.css, use abc.less and variables.less as source". The line below is the actual command which will create the target (note that you need to add a tab before this). $< is an automatic variable which refers to the first source file, which for the example given would be abc.less, and $@ refers to the name of the target.

The next target is less, which just asks make to build style.min.css and dark-theme.min.css. The trick with .PHONY is that less is not actually a file we want to build, so we make it so whenever make less is called, make initiates the build process, and builds the targets based on the %.min.css rule. If we did not add the .PHONY line, any file actually named "less" would interfere with our plans.

Why (and when) you should care

When you're working with something that does not have its own botique build tool (like npm, maven, cargo, you get the point), Make is a great tool to get things done. Even when you're mucking about with something like Java, it can be supremely useful if your focus is on doing things quick and be done with coding in Java as soon as possible.
