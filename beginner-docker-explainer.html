Docker for the uninitiated

Posted on Sep 01, 2023 in blogpost

Image by Karl Ryan @kylry on Unsplash

What's a "Docker" anyway

You might have heard of Docker before, even in passing. You might have even noticed that according to the Stack Overflow developer's survey 2023, it is the most-used developer tool.
Docker allows you to run applications in containers, which are light-weight virtual computers that use the computing resources of the host (what you run Docker on), but otherwise are effectively separated from it. You can run many of these containers, all with their own applications running on it, and Docker handles the creation, resource management, logging, exception handling and so on for you. With just a few commands, for example, you could have a Large Language Model running on your system without having to install anything other than its image, and without having to worry about it crashing or accessing your private data.

Disclaimer

Like all other beginner-oriented tutorials on this blog, this tutorial is merely a reference to point folks to if they ask me to explain something. Some concepts will be simplified for didactic reasons, however I will do my best to not share untrue information.

How to install

If you're on Mac OS or Windows, using Docker Desktop might be the best solution as it sets up a Virtual Machine (VM) for the Linux-based Docker images to use (which is the vast majority of them). On Windows, you might also use WSL2 directly (Docker Desktop can also use it instead of a VM, which is more efficient).

On Ubuntu, sudo snap install docker works perfectly fine, but for other Linux distributions, follow the instructions here.

So what's a Docker Image

An image is basically a bundle of code that runs in a container. You can just download the image for whatever application you want to run and immediately get started without having to install anything else it might depend on.
For example, if you look at the WordPress image, it includes absolutely everything one might need in order to run the blogging software. Contrast this to the process of installing WordPress directly on your computer, where you would need other software installed like the Apache HTTP server, PHP (the programming language used in WordPress), and a database, to name a few (okay, the database is not included in the WordPress image, but we'll get to that)

Running a container

Usually, the page for the docker image will have all of the instructions you might need in order to set the application up, so read it carefully. A few things to note:

  • Any applications running inside a docker container can't access the network that your computer is on by default (that includes the internet). Look at the image instructions carefully in order to find out how to access the application on your computer (hint: this usually involves publish-ing ports using the syntax -p host_port:application_port)
  • Docker containers can't access your computer's secondary storage automatically, you would have to mount any directories you want to share manually using the -v flag.

Docker compose?

So as we discussed earlier, simply running the WordPress image is not actually enough, since it doesn't have a database for storage. Luckily for us, getting a database up and running is as simple as getting a Docker image for it and using that. Since the WordPress and database containers are intertwined, and only together form one whole application, it would be nice to logically group them together. A tool to do that is docker compose. You declare exactly which services you want in a structured manner in a directory with a docker-compose.yml file. This is the preferred way to run all Docker applications nowadays, so you'll probably find examples for whatever image you wish to use.

version: '3.1'
services:
wordpress:
    image: wordpress
    restart: always
    ports:
    - 8080:80
    environment:
    WORDPRESS_DB_HOST: db
    WORDPRESS_DB_USER: exampleuser
    WORDPRESS_DB_PASSWORD: examplepass
    WORDPRESS_DB_NAME: exampledb
    volumes:
    - wordpress:/var/www/html
db:
    image: mysql:5.7
    restart: always
    environment:
    MYSQL_DATABASE: exampledb
    MYSQL_USER: exampleuser
    MYSQL_PASSWORD: examplepass
    MYSQL_RANDOM_ROOT_PASSWORD: '1'
    volumes:
    - db:/var/lib/mysql
volumes:
wordpress:
db:

The example here is taken directly from the WordPress Dockerhub page and works without any changes. To write such files on your own, you would have to read up a little about YAML, but other than that all the fields are self-explanatory.

What's next

Because of the popularity of Docker, you will almost definitely find Docker images for almost any web-based application that exists. You can run applications like Calibre and Jellyfin to access all of your content over your local network from any device, which is what I do at home. Like I mentioned earlier, you can run an LLM, like here. Note how much easier it is to set it up with Docker than without. Hope you have a fruitful journey running (and maybe developing?) containerised applications.
